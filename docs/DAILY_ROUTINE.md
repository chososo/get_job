# 매일 오전 5시 작업 지침

기준 시간대: Asia/Seoul. 프로젝트: `quant-career-desk`. 저장소: `https://github.com/chososo/get_job`.

1. PROJECT_GUIDE.md와 최근 수집 상태를 읽는다. 브라우저 보관함, 백업, `.local/`, `.env`, 경험/지원서는 읽거나 수집하지 않는다.
2. 실행 시점 기준 날짜를 확인한다. `python3 scripts/collect.py --pages 3`으로 공개 수집을 실행한다. 개별 소스가 실패하면 기존 자료를 유지한다.
3. `sources.json`의 미지원/부분 수집 경로를 공개 웹 검색과 원문 확인으로 보완한다. 국내 퀀트·운용·ETF·인덱스·금융리스크·파생평가 인턴/신입이 우선이다. 해외는 GB/HK/SG/PL/JP만 포함한다. 현지어 필수면 제외, 언어·학위·비자 불명은 확인 필요로 분류한다.
4. 최근 공고뿐 아니라 기존 미마감 공고의 접수기간·종료·문구 변경도 확인한다. 새 공고를 전부 지원 가능이라고 분류하지 않는다. 공개 제목·필수 사실·짧은 검증 근거·원문 URL만 `scripts/import_jobs.py`로 넣는다. 첨부만 있고 요건을 확인하지 못하면 review로 남긴다.
5. 중복은 원문 ID/공식 지원 URL로 확인한다. 회사·제목 유사성만으로 기존 공고 ID를 바꾸지 않는다. 사용자 별표·일정 연결은 public job ID에 의존한다.
6. `web/data/latest-run.json`을 확인하고 새 공고/실질 변경/마감 건수를 정리한다. 검증 시각만 바뀐 것은 신규/업데이트 알림에 넣지 않는다.
7. 공개 데이터 검사와 관련 테스트, 빌드를 실행한다. 오류를 수정하고 검증한다. 성공한 공개 데이터만 반영한다.
8. 현재 브랜치와 원격 상태를 먼저 확인한다. 사용자 변경을 덮어쓰거나 강제 푸시하지 않는다. 공개 데이터 `web/data/jobs.json`, `web/data/latest-run.json`만 명시적으로 stage하여 변경을 commit/push한다. 코드 변경이 필요하면 목적을 설명하고 검증 후 별도 commit한다. 개인정보가 섞인 파일을 올리지 않는다.
9. 가능한 경우 Pages 배포 완료 상태를 확인한다. GitHub 인증이 없거나 배포가 실패하면 로컬 데이터는 보존하고 사용자의 조치가 필요한 상태로 알린다. 알림에 비밀값을 출력하지 않는다.
10. 의미 있는 신규/변경/마감, 새 수집 실패, 발행 실패, 필요한 사용자 조치가 있을 때만 알려준다. 변화가 없거나 반복되는 비실행 가능 정보만 있으면 조용히 종료한다. 같은 접근 제한을 매일 반복 알림하지 말고 변화 또는 해결 조치가 필요할 때 알린다.

처음 연결하는 소스의 적법한 공개 접근 범위를 지킨다. 카페 로그인·CAPTCHA·접근 통제를 우회하지 않는다. 컴퓨터가 꺼져 있거나 예약 작업이 실행되지 못하면 공고 데이터에 마지막 검증 시각이 남아야 하며 다음 실행에서 누락 기간을 보완한다.
