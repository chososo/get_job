확인 기준: 2026-09-08 18:42 KST. 요청에 따라 웹앱·수집 코드·공개 피드는 변경하지 않고, 재검색 결과와 결함을 먼저 보고한다. 이 문서는 공개 채용 사실과 출처만 담는다.

## 1. 결론

기존 피드의 미마감 후보 34건은 금융투자협회 14건, WorldQuant 3건, Jane Street 17건에서만 나왔다. 9건은 `open`, 25건은 `review`였다. 사용자가 지정한 사이트 전체를 실제 수집한 결과가 아니다. 나머지 사이트를 설정에 등록하고 수동 보완 지침에 적어 둔 것만으로 수집을 완료한 것으로 취급한 것이 문제다.

LS증권은 원문 자체가 없었던 것이 아니다. 금투협 공고 41952가 수집 캐시의 제외 목록에 있었고, 현행 분류 함수를 적용해도 직무 분류가 없어 탈락한다. 자소설닷컴과 잡코리아에서도 공고를 확인했다. 키움증권도 자소설닷컴·캐치·회사 지원 페이지에 존재한다.

이번에는 최초 지정 9개 URL과 이후 언급한 잡코리아를 모두 접근·검색했다. 아래 표는 실제 확인 범위이며, 모든 사이트의 모든 과거 글이나 로그인 뒤 자료까지 검증했다는 의미는 아니다. 특히 오래된 상시/ASAP 공고는 현재 채용 중이라고 단정하지 않는다.

## 6. 현재 스크리닝은 어떻게 작동하는가

현재 수집 스크립트는 GPT API를 호출하지 않는다. 제목·본문에 대한 정규식/키워드 규칙으로 분류한다. 로컬 서버의 GPT 연결은 작성 도우미 기능용이며 채용 수집과 연결되어 있지 않다. 이번 원문 재검색·대조는 이 대화의 에이전트가 수행한 별도 검토다.

확인한 코드: `scripts/collect.py` 27~97행.

1. **제목 중심 직무 분류:** 본문의 일부 예외 외에는 제목에서 ETF·퀀트·리스크·운용 등 단어를 찾는다. LS처럼 ‘신입 공개채용’이라는 통합 제목 안의 리스크·RA 직무는 놓친다. 하나의 공채를 지원 가능한 직무 단위로 읽지 않는다.
2. **경력 요건 확인 순서 오류:** 제목에 신입·인턴·junior가 있으면 경력 연수를 검사하기 전에 신입/인턴으로 반환한다. 경력 정규식도 ‘관련 업무 10년 이상’처럼 ‘경력’이라는 단어가 없는 표현을 놓친다. 1~2년 필수 경력도 충분히 배제하지 않는다.
3. **과도한 일괄 확인 필요:** 해외 공고는 구체적 요건 확인과 무관하게 기본 review로 만들고, 기한이 없는 상시 공고도 주로 review가 된다. `New Grad` 표현도 제목 신입 규칙에 빠져 있다. 결과적으로 사용자가 이미 판정 가능한 조건까지 다시 읽어야 한다.
4. **저장 결과 재심사 누락:** 캐시와 기존 공고를 가져올 때 본문 필수 조건을 전부 다시 검사하지 않는다. 언어 제외 규칙이 있어도 이전에 저장된 잘못된 open 판정이 남을 수 있다.
5. **제외 키워드 범위가 지나치게 넓음:** 제목의 영업·운용지원·심사역·부동산 등을 일괄 제외한다. 실제 관련 업무를 지원하는 Assistant나 통합 공채의 다른 부문까지 잃을 수 있다. 사용자가 요청한 기업 재무·전략 직무를 담는 별도 분류도 없다.
6. **전체 경로 실행을 입증하지 않음:** sources에 있는 수동 경로는 수집 스크립트가 건너뛴다. 별도 웹 검토 지침은 있지만, 필수 사이트별 확인 기록이 없으면 완료할 수 없도록 막는 절차가 없다.

## 7. 보고 후 적용할 수정 범위

이 절은 제안이며 아직 구현·배포하지 않았다.

- 필수 사이트별 실행 기록을 남긴다: 목록/검색 범위, 후보 수, 본문 확인 수, 적합·제외·보류 수, 이유, 확인 시각. 미실행·조회 실패·0건을 각각 구분한다. 3개 어댑터 실행만으로 전체 수집 완료를 표시하지 않는다.
- 카페는 위 실제 채용 게시판들을 명시적으로 순회한다. 최초 목록 이후 과거의 미마감/상시 공고도 다시 확인한다. 공고 모음에서 발견한 기업의 공식 채용 목록도 지속 확인 대상으로 연결한다.
- 통합 공채 본문을 직무별로 읽되 원 공고 ID와 지원 트랙을 보존한다. 동일 공채·중복지원 제한 때문에 기회 수를 부풀리지 않는다.
- 필수 경력, 필수 언어, 학위·졸업연도, 지역 대학 재학 제한, 근무 가능 기간, 마감 상태를 먼저 판정한다. 우대사항은 필수사항으로 승격하지 않는다.
- 공개 공고 상태(접수 중/예정/종료)와 개인 적합도(적합/필수조건 불일치/개인정보 입력 필요)를 분리한다. 확인 가능한 미달 사유를 review로 떠넘기지 않는다.
- 본문을 검토하지 못한 후보는 추천 기본 목록을 채우는 데 사용하지 않고 조사 대기 목록으로 관리한다. 기존 공고도 같은 기준으로 재심사한다.
- ‘대기업·재무/전략’ 영역을 별도로 두고 IR, 자금, 재무분석, 전략투자, 투자심사 등 관련 신입 직무를 담는다. 이번에 확인한 모비스 2개 공고가 구체적인 초기 사례다.
- GPT API를 붙인다면 공개 공고 본문·이미지/첨부의 내용을 구조화하여 직무별 필수/우대조건과 출처 근거를 추출하게 한다. 경력·언어·마감의 확정적인 제외 조건은 별도 검증한다. 모델만 붙여도 수집하지 않은 사이트의 공고가 저절로 생기는 것은 아니다.
- API 키는 로컬에만 저장하며 공개 GitHub Pages 코드에 넣지 않는다. 공고 스크리닝에는 공개 채용 정보만 전달한다. 이번 작업에서는 API 키를 요구하거나 유료 호출하지 않았다. [OpenAI 구조화 출력 공식 문서](https://developers.openai.com/api/docs/guides/structured-outputs)는 형식 제약을 지원하지만 내용 오류까지 없애 주지는 않는다.

## 8. 현재 변경 상태

이번 재검색 결과는 이 보고서에 저장했다. 앱 코드, 공개 공고 JSON, 자동화 설정, GitHub Pages는 변경하지 않았다. 따라서 위 누락 공고가 이미 홈페이지에 추가되었거나 매일 전체 사이트 수집이 자동으로 완성되었다고 볼 수 없다. 다음 구현에서는 위 확인 기록을 재사용하되 게시 시점의 마감·종료 여부를 다시 확인해야 한다.
