# Quant Career Desk

퀀트·자산운용·ETF·금융리스크·파생상품평가의 인턴/신입 공고, 지원 캘린더, 경험과 지원서를 관리하는 개인 웹앱입니다.

- 저장소: https://github.com/chososo/get_job
- 홈페이지: https://chososo.github.io/get_job/
- 전체 개발 지침: [PROJECT_GUIDE.md](PROJECT_GUIDE.md)
- 일일 작업 지침: [docs/DAILY_ROUTINE.md](docs/DAILY_ROUTINE.md)

## 개인정보 보관

공개 웹앱과 채용 사실 정보만 GitHub에 올립니다. 경험·지원서·별표·개인 일정은 **사용 중인 브라우저의 IndexedDB에 암호화**하여 저장합니다. 비밀번호와 복호화 키는 잠금 해제 세션의 메모리에만 있습니다.

처음 사용할 때 10자 이상의 비밀번호로 보관함을 만드세요. 비밀번호를 잊으면 복구할 수 없습니다. 설정의 **암호화 백업 다운로드**로 별도의 로컬 폴더에 백업하세요. 브라우저 데이터 삭제, 다른 기기/브라우저 사용, Pages에서 로컬 화면으로 이동할 때는 백업 복원이 필요합니다.

로컬 저장은 브라우저 출처 단위입니다. 같은 `chososo.github.io`에 있는 다른 앱과 완전한 보안 격리를 보장하지 않습니다. 별도 도메인 또는 로컬 전용 실행으로 격리를 강화할 수 있습니다. 브라우저와 기기를 타인에게 열어주거나 잠금 해제된 페이지에서 악성 코드를 실행하면 암호화만으로 보호할 수 없습니다.

## 사용 방법

1. 국내/해외 공고에서 분야와 상태를 선택합니다. `지원 가능`은 접수기간과 주니어 표기를 확인한 후보이며 학위·세부 자격은 원문에서 최종 확인하세요.
2. 별표를 누르면 보관함을 열고 중요 공고에 저장합니다.
3. 공고의 `작성 일정 잡기`로 초안·검토·제출 일정을 추가합니다. 공고 원문 마감일과 개인 작성 일정은 별도로 표시합니다.
4. 경험 보관함에 상황·과제·행동·성과를 입력합니다.
5. 작성 도우미에서 회사/직무/문항을 입력하고 경험을 선택합니다. 초안 구조를 만들거나 GPT 요청문을 복사할 수 있습니다.
6. `로컬에 저장`을 누르면 내 지원서에 회사·직무별로 보관됩니다.

## 로컬 도우미와 설정

Python 3.11 이상과 `requirements.txt`의 패키지를 설치합니다. 이 Mac에는 동적 공고 열람용 Playwright 브라우저도 설치했습니다. `Career Desk 시작.command`를 더블클릭하면 도우미가 실행됩니다. 터미널에서 실행할 수도 있습니다.

```sh
python3 -m pip install -r requirements.txt
python3 scripts/local_server.py
```

도우미 실행 창을 유지하고 [홈페이지의 수집 현황 · 설정](https://chososo.github.io/get_job/#settings)을 엽니다. 브라우저가 로컬 네트워크 접근을 요청하면 허용합니다. 서버는 `127.0.0.1:8765`에서만 동작합니다.

- **키 없음:** 규칙 기반 심사.
- **키 저장:** GPT-6 Astra (`gpt-6-astra`)가 공개 공고의 본문·문자 인식 결과를 읽어 직무, 필수 자격, 마감과 근거를 정리합니다. 별도 API 요금이 발생합니다.
- **키 삭제:** 다음 실행부터 규칙 방식으로 돌아갑니다.

새로고침할 때 키를 다시 묻지 않습니다. 키는 `.local/openai.json`에 소유자 읽기/쓰기 권한으로 저장하고 화면·Git·Pages·로그에는 반환하지 않습니다. 키를 이 대화에 보내지 않아도 됩니다. 실행 중 키를 변경하면 다음 수집에 적용됩니다. API 접근 오류는 표시하고 해당 공고를 검토 대기로 남깁니다. 반복 오류 3회 후 추가 API 요청을 중단합니다.

개인 경험·지원서는 공고 수집에 사용하지 않습니다. 작성 도우미에서 **GPT로 작성·다듬기 → 확인한 내용 전송**을 선택한 경우에만 표시된 개인 자료를 OpenAI로 보냅니다. `store:false`를 지정하지만 OpenAI 정책에 따른 보존이 있을 수 있습니다. [공식 데이터 정책](https://developers.openai.com/api/docs/guides/your-data)

다른 컴퓨터의 동적 페이지 수집을 준비하려면 Node.js와 Playwright를 설치합니다. macOS의 채용 이미지 문자 인식에는 Xcode 명령줄 도구의 Swift/Vision을 사용합니다. 해당 도구가 없거나 첨부를 읽지 못하면 미확인으로 남깁니다.

```sh
npm install --no-save playwright
PLAYWRIGHT_BROWSERS_PATH="$PWD/.local/browsers" npx playwright install chromium
```

## 공고 새로고침과 수집 범위

상단 **공고 새로고침**은 저장된 파일만 다시 읽는 버튼이 아닙니다. 로컬 도우미가 전체 등록 사이트를 다시 확인하고, 원문 자격요건을 재심사한 뒤 공개 데이터를 저장합니다. 화면의 진행 상태와 결과를 확인하세요. 수집 중 탭을 닫아도 도우미가 켜져 있으면 계속 실행합니다. 한 번에 하나의 수집만 실행합니다.

동일한 수집기를 명령줄과 예약 루틴에서도 사용합니다.

```sh
python3 scripts/refresh_jobs.py --pages 3
# 공개 데이터 두 파일만 GitHub에 게시하려면:
python3 scripts/refresh_jobs.py --pages 3 --publish
```

`scripts/collect.py`도 위 수집기로 연결됩니다. `sources.json`의 모든 사이트를 실제 시도하고, 사용자 추가 사이트는 로컬 `.routine-sites.json`에서 읽습니다. 금융투자협회, FCB, 네이버 카페의 여러 채용 게시판, 슈퍼루키, 자소설, LinkedIn, 캐치, 원티드, 잡코리아 및 기업 공식 사이트를 순회합니다. 사이트별 목록/상세 한도, 실패, 확인 수를 기록합니다. 모든 과거 글·로그인 뒤 자료까지 완전 수집했다는 뜻은 아닙니다.

필수 경력·현지어·실제 마감 상태를 먼저 판정합니다. 추천 기본 목록에는 접수 중/예정 공고만 표시하고 불명확한 공고는 **조건 확인 필요** 필터로 분리합니다. 공개된 학위·졸업연도·근무조건은 상세에 표시하며 개인의 충족 여부를 추측하지 않습니다. 원티드는 화면의 상시채용 문구보다 실제 종료 상태를 우선합니다. 첨부를 읽지 못했다면 지원 가능으로 단정하지 않습니다.

공개 출력은 `web/data/jobs.json`과 `web/data/latest-run.json`입니다. 수집 실패는 0건과 구분하고 기존 자료와 검증 시각을 유지합니다. `public-watch.json`에는 별도 검토한 공개 공고의 재확인 주소·근거가 있습니다. 검토 근거가 원문과 맞고 원문이 변경되지 않았을 때만 보완된 사실을 사용합니다.

새 수집 뒤 화면과 캘린더는 로컬 결과를 즉시 읽습니다. 공개 데이터 두 파일은 안전한 Git 상태일 때 자동으로 업로드합니다. 업로드 실패 시 로컬 결과를 보존하고 상태를 표시합니다. Pages 반영은 GitHub 배포 완료 후 다른 기기에도 보입니다.

GitHub Pages는 정적 화면이므로 자체적으로 수집하거나 API 키를 보관하지 않습니다. 공개 저장소에는 배포 워크플로만 있습니다.

## GitHub Pages 배포

저장소 Settings → Pages → Build and deployment → Source를 **GitHub Actions**로 지정합니다. `main`에 공개 웹 파일을 올리면 `Publish Career Desk`가 `web/` 중 허용된 파일만 빌드·배포합니다.

```sh
python3 scripts/build.py
```

`dist/`에 실제 공개 산출물이 생성됩니다. 개인 백업, `.local/`, `.env`, 테스트 결과는 포함하지 않습니다. 기존 사용자 파일을 공개하기 위해 상위 폴더에서 `git add .`를 실행하지 마세요.

## 검증

```sh
python3 -m unittest discover -s tests -p 'test_*.py'
node --test tests/*.test.mjs
node --check web/app.js
python3 scripts/build.py
```

현재 테스트는 마감일·시차·신입/언어 분류·변경 감지·수집 실패 시 보존·암호화·변조 거부·공개 도구 계약을 다룹니다. GPT 유료 호출은 API 키 입력 전에는 검증하지 않습니다. 실제 브라우저 상호작용 QA와 실제 WebMCP 지원 브라우저 검증 여부는 인수인계 기록에 구분해 남깁니다.

## 알려진 한계와 다음 작업

- 공개 접근이 제한되거나 목록 구조가 변경되면 일부 수집에 실패할 수 있습니다. 수집 현황에서 실패와 한도를 확인할 수 있습니다.
- 키가 없으면 규칙 방식입니다. AI·문자 인식도 오판할 수 있으며 복잡한 혼합 직무나 첨부 누락은 추가 원문 확인이 필요합니다.
- 동일한 공식 지원 상세 주소는 병합하며 기존 ID를 유지합니다. 회사명만 같다는 이유로 서로 다른 공고를 합치지 않습니다.
- 개인 자료 자동 동기화, Google/Apple Calendar 연동, 클라우드 알림 서비스는 포함하지 않습니다.
- PDF/DOCX 서식 편집은 아직 없으며 텍스트 기반 자소서/CV 관리와 다운로드를 제공합니다.
# 채용 사이트 직접 추가

홈페이지의 **채용 사이트 관리 → 기업명 · 링크 추가**에서 기업명만 입력하거나 채용 주소를 붙여넣습니다. NICE평가정보 등 등록된 기업은 주소를 연결하고, 새 기업명은 공식 주소를 찾을 대상으로 저장합니다. 목록은 암호화 보관함에 저장되어 기존 백업에도 포함됩니다.

도우미가 연결되어 있으면 추가·수정·일시정지·삭제를 바로 전달합니다. 연결이 없으면 **루틴에 전달 · 파일 다운로드**를 눌러, 예약 작업을 실행하는 Mac의 `Downloads` 폴더에 원래 파일명으로 저장하세요. 다음 예약 작업이 최신 파일을 읽습니다. 다른 다운로드 폴더를 사용하는 경우 이 파일만 Downloads로 옮겨주세요. 도우미와 연결하거나 파일로 전달하기 전에는 예약 작업에서 볼 수 없습니다.

전달 파일은 기업명·공개 주소·활성 여부만 담는 로컬 파일이며, 자소서·경험·키는 포함하지 않습니다. `.routine-sites.json`에 반영되고 GitHub에는 업로드되지 않습니다. 파일은 전체 목록이므로 최신 파일의 삭제·일시정지도 반영됩니다. 기본 루틴 사이트는 이 개인 목록과 별개입니다. 기업명만 저장한 대상은 공식 주소 확인이 필요하며, 사이트 추가가 공고 수집 완료를 뜻하지는 않습니다.
